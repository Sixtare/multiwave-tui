# AGENTS.md

Ratatui terminal audio visualizer (Rust, edition 2024). Captures system output audio with cpal, computes a spectrum with realfft, and renders mirrored bars. There is no README, CI, workspace, or task runner config — Cargo is the source of truth.

## Commands

- `cargo run` — the TUI writes to **stderr** (`CrosstermBackend` over a buffered `std::io::stderr()`), so run it in a real terminal and don't pipe stdout to inspect it. It still launches when audio capture is unavailable, just without bars.
- `cargo test --lib` — preferred test command. Inline tests in `src/app.rs`, `src/audio_processor.rs`, `src/event.rs`, `src/sound_device.rs`, and `src/update.rs` are reachable from both `main.rs` and `lib.rs`; plain `cargo test` runs them twice (lib + bin harness). Tests in `src/lib.rs` only run under the lib harness.
- `cargo test --lib <filter>` — run one test, e.g. `cargo test --lib app::tests::test_app_gain_adjustment`.
- `cargo test --lib -- --skip test_sound_device_filtered_list` — headless-safe run. That test asserts at least one real output device exists and fails on machines without audio hardware.
- Linux builds need ALSA headers and pkg-config (`libasound2-dev`, `pkg-config`) for `alsa-sys`.
- Windows builds use the default cpal WASAPI backend and need no extra system packages beyond the Rust MSVC toolchain.
- Full check: `cargo fmt --check && cargo clippy --all-targets && cargo test --lib -- --skip test_sound_device_filtered_list`.

## Architecture & Code Conventions

- **Language:** All source code comments, docstrings, and error messages must be kept in **English**.
- `src/main.rs` is the entrypoint and redeclares every module itself; `src/lib.rs` repeats that list so tests compile without `main`. When adding a module, register it in **both** files.
- `main.rs` owns the event loop and the `SoundDevice`; `App` only holds pure UI state and device name strings. `update()` / `apply_batch()` mutate `App` and return `AppAction`s (`ChangeDevice`, `RecoverLostDevice`, `PollDevices`), and `main` performs the hardware work afterward. Keep audio hardware side effects out of `App` and `update`.
- `event::EventHandler` runs a crossterm polling thread and emits `Event::Tick` every ~16 ms (60 FPS); the cpal callback sends `Event::AudioBars` through the same mpsc channel.
- The main loop calls `EventHandler::next_batch()`, which blocks for one event and drains the rest into an `EventBatch` (tick count, latest bars only, `BatchEvent`s in order). `update::apply_batch()` applies it and returns a `BatchOutcome`; `main` runs the actions and draws once per batch, only when the batch had a tick or a key press (a key is drawn right away, not at the next tick; audio-only batches still wait for a tick). Once an event quits, the rest of the batch is discarded. Never go back to drawing per event: when a draw is slower than the tick + audio rate (Windows consoles), the channel backlog grows without bound and input lags further and further.
- The terminal backend writes to a 256 KiB `BufWriter<Stderr>` (`OUTPUT_BUFFER_CAPACITY`); unbuffered stderr turns every crossterm command into its own console write, and the default 8 KiB splits large frames.
- `event::forward_terminal_event()` forwards key presses, mouse, and resize events, and deliberately ignores `FocusGained`/`FocusLost`. Windows always emits focus events and they cannot be disabled; never panic on an unhandled crossterm variant, because killing the event thread leaves audio bars flowing while the UI stops responding to keys.
- `Tui::reset()` disables mouse capture before raw mode: on Windows, `DisableMouseCapture` restores the console input-mode snapshot taken while raw mode was active, so it must run before `disable_raw_mode()`.
- `sound_device.rs` captures the output **sink monitor**, not a microphone. On Linux, `init_capture_env()` sets `PIPEWIRE_ALSA` / `PULSE_SOURCE` only if unset; don't overwrite those variables when the user already set them. On Windows, cpal uses WASAPI loopback automatically when a render endpoint is opened as an input stream.
- On Linux, `sound_device.rs` filters out global ALSA plugin aliases (anything without `:CARD=` in its PCM id), technical duplicate drivers (raw `hw:`), dummy sinks ("Discard all samples"), and unconfigured hardware ports. On Windows it deduplicates active render endpoints by cpal `DeviceId`, because different endpoints may share the same friendly name.
- `SoundDevice` polls the default output every second on Windows, rebuilds capture when the selected "Default Output" changes, and falls back to the current default if an explicitly selected endpoint disappears. `Event::AudioDeviceLost` triggers that recovery path.
- Bar smoothing (`App`) is an option, off by default (`S` toggles it; `AppAction::SetSmoothing` forwards it to the capture's `CaptureSettings`). Off: the original response, where every audio frame and every tick moves the bars towards the targets with fixed factors 0.65 up / 0.20 down, and the processor does not average the treble. On: an audio frame only stores the target bars; `tick()` decays the targets and moves every bar towards them once per tick, faster up (`attack_factor` 0.40) than down (`decay_factor` 0.12). Moving continuously every tick keeps the bars fluid, and falling slower than rising keeps a bar that dips and rises again within a few frames from flickering. Don't add a peak hold: it made the bars feel stiff. `App.audio_bars` already holds final 0.0..=1.0 heights (the audio processor applies the dB scale, the automatic sensitivity and the manual gain), so rendering reads them as they are.

## DSP & Audio Pipeline (`src/audio_processor.rs`)

- Interleaved audio is downmixed to mono `(L + R) / 2`. For multichannel layouts, only the front left/right channels are averaged so center/LFE/surround content does not dominate the bars.
- One bars frame comes out per 1024 mono samples (~47/s at 48 kHz). Each step runs two Hann-windowed forward FFTs via `realfft`: 1024 samples for the treble and 4096 (the latest four steps) for the bass. Bars centered below 150 Hz read the long FFT, so the narrow bass bars span several bins; the rest read the short one. Magnitudes are scaled so a full-scale sine reads 0 dB and noise reads the same level in both FFTs (a bass tone therefore reads 6 dB hotter).
- Output is grouped into `bar_count` log-spaced bars (32 to 256, 40 Hz to 16,000 Hz) using the stream's actual sample rate, not a fixed 44100 Hz value. `AudioProcessor::set_num_bars()` rebuilds the layout without dropping buffered samples.
- A bar narrower than one FFT bin is read at its center frequency by linear interpolation between the two surrounding bins, instead of repeating a neighbour's value as a plateau.
- Bins combine average and peak magnitude (`0.5 * avg + 0.5 * max`) to preserve rapid transients (cymbals, snares). Because the peak of more bins is higher, that rule overstates noise in wide bars; each bar is divided by `noise_bias(bins)` (the expected overstatement for Rayleigh-distributed noise) so noise reads the same whatever the bar width.
- Frequency tilt: a gain of `3.01 + EXTRA_SLOPE_DB_PER_OCT` (1.5) dB per octave around 1 kHz, computed from each bar's center frequency. The 3.01 dB/oct part flattens pink noise (tests check it stays within ~2 dB across the bars for 32 to 256 bars); the extra part lifts the treble because music is darker than pink noise. Don't replace it with a per-index weight: the balance would change with the bar count.
- Treble smoothing (only when the smoothing option is on, `set_smoothing`; turning it on reseeds the average): the treble bars' power (squared magnitude) is averaged over time with a ~40 ms time constant (`TREBLE_SMOOTHING_SECONDS`) before the dB conversion. The 1024-sample FFT gives independent, noisy frames, while the bass FFT already overlaps 75% between frames; without this the mids jittered 3 to 4 dB per frame against about 1 dB for the bass. Power averaging keeps the mean level of noise unchanged. The bass bars are not smoothed.
- Heights are linear in dB: `DB_WINDOW` (50 dB) below the 0 dB top maps to 0.0..=1.0. A narrower window gives more contrast on dense material; a wider one shows more detail.
- Automatic sensitivity (the cava `autosens` rule): when any bar's height exceeds `PEAK_TARGET_HEIGHT` (0.75, so the loudest bar leaves headroom instead of touching the top) the sensitivity drops ~2% per frame, otherwise it rises ~0.1% per frame (rates scaled to the real frame rate). Until the first overshoot it climbs 10x faster, up to 10x, so a quiet start fills the display in about a second. Digital silence (peak below ~-80 dBFS) leaves it alone. A new capture stream (device switch) starts over at 1.0.
- The user's manual sensitivity (`App.gain`, Up/Down) is applied after the automatic part, as a dB offset on the heights, so the two never fight. `apply_batch()` emits `AppAction::SetGain` when it changed; `main` forwards it to `SoundDevice::set_gain()`, which stores it in the same shared `CaptureSettings` as the bar count (read by the capture callback on every block).

## UI & Rendering (`src/ui.rs`)

- The visualizer occupies 100% of the available vertical height, centered dynamically on the screen without enclosing block borders.
- The visualizer is a `Soundwave` widget that writes cells straight into the `Buffer`. Don't go back to building a `Paragraph` of per-cell `Span`s: the per-cell `String` allocations and centering cost more than half the app's CPU. Each bar takes `COLUMNS_PER_BAR` (2) columns; on a terminal narrower than the row, the treble side is clipped.
- `Tui::draw_if_changed()` skips the draw when `ui::FrameState` (everything `render` reads, plus terminal size) matches the last drawn frame, so silence costs almost nothing. Anything new that `render` reads must be added to `FrameState`, or changes to it won't show until something else redraws.
- Bar count: `App` keeps the count the user chose (`chosen_bar_count`) and the count shown (`bar_count` = chosen clamped to `MIN_BARS`..=`min(MAX_BARS, width / COLUMNS_PER_BAR)`, never below 32 even if clipped), so bars shrink on a narrow terminal and grow back on resize. `apply_batch()` applies the terminal width first and emits one `AppAction::SetBarCount` when the shown count changed; `main` forwards it to `SoundDevice::set_num_bars()`, which updates an atomic in `CaptureSettings` that the capture callback reads, so changing it never rebuilds the stream. `App::update_audio_bars()` drops frames whose length differs from `bar_count` (stale frames from before a change). A ~1.5 s `N bars` notice appears in the top-right corner after each key press; changing the sensitivity shows a matching `sensitivity N.NNx` notice (cyan text, no background) stacked below it, toggling smoothing shows `smoothing on`/`smoothing off` below those, and confirming a bar color shows `color: Gradient`/`color: <name>`.
- Symmetrical layout:
  - Upper half: normal bars growing upward using base-anchored Unicode blocks (` ▂▃▄▅▆▇█`). Colors come from `App.palette` (`src/palette.rs`): by default bass cyan, mids green, treble magenta (one color per third of the bars), or one color for every bar.
  - Center line: subtle horizontal divider (`──`).
  - Lower half: upside-down mirror effect growing downward using top-anchored blocks (` ▔▀█`), with attenuated amplitude and the palette colors at half brightness (`BarColor::mirror_color`, computed from fixed RGB values), or the very same colors as the bars when the popup's `Mirror` checkbox is off (`Palette.mirror_dimmed`).
- Device selection popup renders a rounded bordered box using `Clear` over the visualizer, highlighting the selected cursor in cyan and tagging the active device with `[Active]`. When the terminal is too short for every device, the popup caps its height, scrolls to keep the selection visible, and shows a vertical scrollbar.

- Bar color popup (`c`): a small rounded box drawn over the still-visible visualizer, five rows: Mode (`Gradient`/`Single color`; Enter toggles it), Bass, Mids, Treble, then after a blank line a `Mirror` checkbox (`[x] Darker`; the whole row is green while on and yellow while off, Enter toggles it). In single color mode Mids and Treble are grayed out, skipped by the cursor, and show the bass color they follow (their own colors are kept for when the gradient comes back). Colors are free 24-bit RGB (`BarColor`, `src/palette.rs`); the default is cyan (0,255,255), green (0,205,0), magenta (255,0,255). Enter on a color row opens the color picker (`src/color_picker.rs`, drawn by `render_color_picker`) in a second box to the right, vertically centered on the same axis as the popup; while it is open the two boxes are centered together on the screen (overlapping the popup's right edge only on a terminal too narrow for both). The picker is a saturation (columns) / value (rows) square, a vertical hue strip, and the picked color's `#RRGGBB` shown below for reading (the value cannot be typed); Tab switches the focus between the square and the hue strip. Every edit goes straight into `App.palette` as a live preview; Enter keeps the color and returns to the popup, Esc/`c` restore the color from before the picker opened. Esc/`c` on the popup itself close it and keep everything chosen; a `color:` notice (`Gradient` or the bass color's hex in single mode) shows if the palette changed. Not persisted. `palette`, `show_color_popup`, `color_row` and `color_picker` are part of `FrameState`.

## Keybindings (`src/update.rs`)

- Popup closed: `q` quits, `c` opens the color popup, Esc opens the device popup, `s` toggles smoothing, Left/`j` bars -8, Right/`l` bars +8 (min 32, max `min(256, width / 2)`), Up/`i` manual sensitivity (gain) +0.10 up to 5, Down/`k` -0.10 down to 0.1 (on top of the automatic sensitivity). `j`/`k` are not vim-style navigation here.
- Color popup open: Up/`k` and Down/`j` move the row, Enter toggles the mode or the mirror checkbox, or opens the color picker, Esc/`c` close, every other key is swallowed, Ctrl+C quits. With the picker open: arrows (and `j`/`k`) move the square cursor or, with the hue strip focused, the hue (one press moves the square cursor exactly one cell, or the hue by 10 degrees, which is finer than a strip row so neighbouring shades like red and pink stay reachable; Shift = a fifth of that, for fine picks), Tab switches between them, Enter keeps the color, Esc/`c` cancel it. The device popup swallows `c`.
- Device popup open: Up/`k` and Down/`j` move selection, Enter activates the highlighted device, Esc closes (`s` is swallowed). Ctrl+C quits in every mode.
- The popup branch returns early and swallows every other key; add new popup keys there explicitly.
